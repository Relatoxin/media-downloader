# Portfolio case study

## Problem

Browser players often expose several technical requests for one video: a master playlist, an active variant, CDN replicas, and separate audio/video formats. A useful downloader must present these as understandable user choices while preserving the headers, cookies, and short-lived URLs required by the source.

## Constraints

- Chrome Manifest V3 and a Windows desktop companion.
- User-confirmed downloads only; detecting a request must not start a download.
- No DRM or access-control bypass.
- Signed HLS URLs can expire during long downloads.
- Cancellation must release Windows file handles before deleting partial files.
- Social sites frequently separate video and audio.

## Solution

The extension groups related HLS candidates and shows the number of downloadable cards rather than raw requests. Social pages are represented by a single page-level task, allowing `yt-dlp` to expose combined video formats and audio-only choices. A loopback API prepares an in-memory task, and the user starts it in the Tkinter app. Downloads run in a spawned process so cancellation can terminate the worker, release handles, and clean only files changed by that task.

## Engineering highlights

- Privacy-reduced diagnostics made a real CDN-replica duplication bug reproducible.
- Format modeling prevents a video-only YouTube stream from appearing as a normal download; the engine pairs it with audio before merge.
- Preview fallback order is player capture, extractor thumbnail, then a video frame generated by FFmpeg.
- Completed video is checked for plausible size and duration before receiving a success state.
- A deterministic local HLS fixture tests the media path without depending on external sites.

## Result

The prototype now has a clear extension-to-app workflow, explicit quality/audio selection, newest-first tasks, persistent output settings, reliable cancellation cleanup, and Explorer selection for completed files. The repository adds pinned dependencies, lint/type checks, automated regression tests, CI, security documentation, and a reproducible contributor setup.
